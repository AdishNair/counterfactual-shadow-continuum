# Cycle 5: continuous asynchronous evidence systems protocol

**Status:** Preregistered on 2026-10-06 before Cycle 5 main outcomes. Implementation and correctness validation may precede collection; every amendment must be dated and preserved in the immutable series. Research question: can local asynchronous CSC preserve production cadence while producing comparable counterfactual evidence with bounded hot state and worker capacity?

## Main factorial, fixed before results

Five modes: K=0 (no mirror), asynchronous cold K=1/K=2, asynchronous warm K=1/K=2 (one mirror each). For each nonzero-K mode use six conditions: normal load with injected shadow service delays 0, 0.12, 0.6 seconds; controlled CPU, memory, and storage pressure each at zero injected service delay. K=0 uses four load conditions without redundant service delays. Thus 28 cells and three paired independent run/seed units (1501–1503), 84 runs. Randomize within seed using a recorded independent order seed, executing runs sequentially to avoid cross-condition interference. Epochs within a run are dependent observations, not independent replication.

Each run: 200 epochs, first 20 excluded from primary summaries, H=6, production pacing target 40 ms, evidence deadline 300 ms, shadow transport timeout 2 seconds, three worker slots, maximum 12 admitted unsettled branch tasks, maximum 16 pending epochs. Warm workers: recycle after 100 tasks or 60 seconds; retain at most 64 completed summaries/duplicate IDs. No deadline increases or settings selected from outcome inspection. Warm processes start/handshake before production pacing; report startup separately, including replacement startup during execution. Both modes use the same admission policy. This is a bounded local pilot below the specification's 500-epoch condition standard, not full validation.

Controlled contention: one reproducible CPU pressure process with logged workload/CPU time; at most 64 MiB explicitly touched memory in a separate pressure process; storage pressure through recorded bounded writes or injected single-writer delays. Declare the exact mechanism in the frozen machine plan. Delayed writes are a service-pressure probe, not proof of physical disk saturation. These deliberately safe loads do not imply whole-host exhaustion or scheduler isolation. Also restrict available workers in the long saturation study below. Log pressure liveness and achieved intensity; an absent/ineffective stressor limits interpretation.

## Metrics and definitions

Production: decision latency, full required production path time, start-to-start cadence p50/p95/p99, errors, missing epochs, authoritative trajectory and workload hashes, throughput/utility consistency, coordinator production CPU where measurable. Record strict 40 ms interval overruns and cumulative schedule drift; Windows pacing jitter makes a strict overrun different from a missed actuation guarantee. Also report full timing distributions. No post-hoc equivalence margin or real-time claim.

Evidence: requested/admitted/accepted completed branches, mirror and alternative rates, complete comparable epochs relative to all requested work (never merely admitted work), partial epochs, no-evidence epochs, expiry/drop/rejection reasons, queue saturation, comparison time and age from production commit. Distinguish physical worker return from coordinator acceptance before deadline and from a complete epoch comparison. Requested/admitted/completed K and resource snapshot belong in every CFR. Incomplete sets have unavailable regret. K=0 is a production baseline, not 100% counterfactual completeness.

Practical availability is described before outcomes: zero coverage means no continuous comparable stream; nonzero coverage below one-third is low, one-third to below two-thirds moderate, and two-thirds or greater high. These equally spaced descriptive labels are not scientifically justified deployment thresholds or pass criteria. Report exact distributions and evidence records/second regardless of label. Report the existing specification's **≥10,000 consecutive epochs at CFR completeness ≥90%** separately; this protocol does not meet its duration requirement. No new numerical success target is invented.

Efficiency: complete comparison records/second, records per observed worker, serialized CFR bytes/complete comparison, and complete records/CPU-second only if total coordinator/worker CPU includes unsuccessful work and is reliable. Do not present successful-task CPU alone as total efficiency. Records/retained MB is optional only with explicit state definition and units. Unavailable metrics stay null, never zero.

## Precollection amendment: operational definitions (2026-10-06)

The independent Astra review is preserved at `research/archive/cycle5/protocol_review/cycle5_protocol_review.md`. It identified six MAJOR definition gaps, not demonstrated runtime failures. The following definitions supersede ambiguity above and must match the frozen machine plan and source. No main outcome has been inspected.

- **Information and deadline:** Each H-tick window is fully generated locally, production simulated, and production outcome available before shadow admission. This is an accelerated post-window common-input experiment, not a live future-information service. The monotonic evidence clock starts at ledger commit entry after the required production path. Each branch result must be validated/accepted strictly before `commit + 0.3 s`; equality expires. Coordinator polling observes completion at discrete loop times, so a worker return before deadline can still expire if validation is later. Full comparison may finalize later because the coordinator serializes epochs in order; report availability time separately from timely branch acceptance. Worker launch-entry, dispatch roundtrip, execution and queue timings describe measured components, not an identified pure process-start effect.
- **Measured cohort and run end:** Main cohort consists of requested epochs 20 through 199 inclusive. Warm-up requests remain active and can occupy capacity; there is no clearing at epoch 20. Long-run online-state plots include all epochs; evidence summaries exclude epochs 0 through 19. After the last production epoch, poll for at most another 0.3 s, honoring each original per-package deadline; expire remaining pending work, close the pool, and classify subsequent results late. Shutdown does not extend eligibility. No workers or production measurements are run in a special improved service phase. Report eventual complete cohort records divided by its measured production span as cohort-normalized yield, separately from complete records finalized before production end divided by that span. Record the additional drain/join/summary duration. Every branch belongs to the epoch that requested it.
- **Admission/exposure:** Freeze existing `ACTIONS` order (`NS_GREEN`, `EW_GREEN`, `BALANCED`) with production action excluded. K=1 requests the first available alternative; K=2 requests both. Mirror is attempted first, then alternatives in that order. No rotating fairness or learned scheduling is implemented; report per-action starvation/exposure. Attempt each branch independently up to the fixed slot/task budgets, drop on full, and retain unsettled running-task permits until actual future settlement. Pending-epoch overflow expires the oldest package; ordered finalization can hold newer packages. Completeness denominator is the number of measured production epochs requesting nonzero K: numerator requires accepted comparable mirror plus every originally requested distinct alternative. K=0 counterfactual completeness is unavailable, not one. Requested, admitted and completed branch denominators are reported separately.
- **Production timers/pacing:** Decision timer begins at epoch start and ends after gateway actuation. Required production-path timer also includes event generation/serialization, anchor writes, input validation and authoritative simulation/outcome creation; it ends before ledger commit. Actual start-to-start cadence includes all preceding coordinator polling/comparison/storage/audit/resource sampling and scheduling overhead. Measured intervals belong to their ending epoch (20 through 199); no second warm-up cut. Sleep targets 40 ms after the previous actual start; overdue epochs proceed immediately, with no skipped simulated decisions and no repayment of accumulated schedule drift. Report intervals greater than 40 ms and drift relative to the ideal grid separately from observed processing-path overruns; they are descriptive scheduling misses, not violations of a validated real-time actuation contract. Replacement readiness waits occur on executor threads while occupying finite capacity; initial readiness occurs before epoch zero. Summary generation occurs only after production and is separately measured.
- **Persistent state and gate:** Retained worker metadata is version, experiment identity, bounded recent assignment IDs, monotonic last epoch, task count, immutable environment baseline and an empty input-integrity sentinel. Validate a field allowlist, empty sentinel and unchanged environment; build fresh anchor/state/model/input/actuator/trace/config for each assignment. Keyed model RNG follows anchor seed/sequence; restore global RNG from anchor for the task and clear it afterward. No mutable model cache or production capability is retained. Reject malformed/duplicate/stale/foreign identities; on integrity, transport, crash or timeout failure destroy the process, replace before another assignment, and recycle at 100 tasks or 60 s before next assignment. Bounded duplicate metadata is supplemented by monotonic epoch rejection after eviction; late results cannot reopen finalized epochs. Bound pending packages (16), unsettled futures (12), executor workers (3, saturation 1), completion cache (64), IPC response queue (1 per worker), and warm response bytes (4 MiB). Cold baseline and HTTP may reject oversized bodies only after collection: disclose that limitation; do not generalize warm preallocation bounds to them. Collection gate requires all listed warm deterministic/reset/credential/replacement/malformed tests and existing authority/replay regressions to pass after any test semantic correction is documented. Fault-extension tests classify recoverable and negative production failures; an unexpected actuation or reset-integrity escape blocks collection.
- **Failure analysis:** No main-run retries or replacement of failed attempts. Preserve every scheduled run's status, prefix artifacts, error and missing production count. Continue independent conditions after safely closing failed processes; abort the campaign on an authority breach, unsafe stressor, or uncontained resource growth. Never pool a failed observed prefix as a complete run. Report missing runs and failed runs in verification and tables. Missing/ineffective pressure helpers invalidate that stress contrast, not the entire run's observed data; CPU/RSS/handle measurements absent or too quantized remain unavailable. Unscheduled smoke/fault tests use separate seed/series identities.

Pressure is ready before epoch zero and stopped/joined before the next run; no extra settling interval is promised. CPU pressure is one unpinned sustained integer-LCG process. Memory pressure holds 64 MiB, increments one byte per 4 KiB page each pass and sleeps 5 ms. Storage pressure rewrites one approximately 4 MiB file on the series volume with stream flush, no fsync and 5 ms sleeps. Measure process CPU seconds, iterations/touch passes/written bytes, duration and liveness. These are limited workload probes, not host-saturation guarantees. Windows host activity is uncontrolled; randomized recorded orders 53002, 53003, 53004 reduce order confounding, not eliminate it. All three paired seed values and all cells remain visible; no significance or equivalence conclusion is permitted.

Online resource sampling occurs each epoch. OLS uses all available per-epoch points, with time from actual monotonic starts where recorded; report first/last quarter distributions, absolute maxima and worker recycle/lifecycle counts. Autocorrelated samples have no independent-observation confidence interval. Structural upper bounds and finite measured trends are separate findings. Current RSS, Python allocations, active worker RSS, and post-production summary peak are distinct quantities. Append-only archival bytes grow separately; persistent disk budget and crash-durable recovery remain open limitations. Exact fractions take precedence over descriptive coverage labels. Specification target is ASCII `>=10,000 epochs` and `>=90% completeness` when passing through reviewer tools that cannot preserve Unicode.
